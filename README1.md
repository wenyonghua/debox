先说明合规边界
我可以帮你做合规的 Spring Boot + MyBatis-Plus + MySQL + Redis 后端系统设计与开发，比如：
用户注册、邀请关系
钱包账本
积分/平台币发放
活动奖励
后台配置
结算记录
风控审计
Redis 缓存、分布式锁、幂等控制
但是你这两张图里包含明显的高风险内容：资金盘、USDT 充值、彩票/开奖、47 倍返奖、多级返佣、团队/代理/工会/董事分润、回购销毁、固定比例释放等。这些在很多地区可能涉及非法彩票、传销、非法集资、赌博、虚拟货币资金归集、证券化发行等法律风险。
所以我不能帮助你搭建一个用于真实上线运营的“资金盘/博彩/多级返佣”系统。但我可以帮你把它改造成一个合规的积分营销 / 活动奖励 / 内部模拟结算系统，并给你完整技术方案。
一、从流程图拆解出来的业务模块
你这两个图可以拆成 6 个核心模块。
1. 用户与邀请体系
   图中有这些角色层级：
   角色	含义
   普通会员	默认注册用户
   挂靠小店 / 小店	中间推广角色
   代理	需要名额、门槛或费用
   工会	高级团队角色
   董事	更高级团队角色
   平台	收取手续费、分润、管理规则
   核心关系是：
   用户注册 DApp
   通过邀请码 / 推荐关系绑定上级
   根据业绩、人数、额度升级为代理、工会、董事
   不同角色享受不同返利比例
   同等级上级存在“平级收益”
   如果做成系统，需要设计：
   用户表
   邀请关系表
   用户等级表
   角色申请/审核表
   等级升级规则表
   团队业绩统计表
2. 充值与钱包体系
   图中充值资产主要是 USDT，另有“小六币”。
   系统上需要至少两个账户：
   资产	用途
   USDT	充值、投注/购买、中奖结算、返佣
   小六币	不中奖奖励、释放、回购销毁、买卖手续费分红
   建议设计成多资产钱包模型，不要在用户表里直接放余额。
   需要有：
   钱包账户
   钱包流水
   充值订单
   提现订单
   冻结金额
   可用金额
   幂等单号
   审计日志
   所有资金变化必须通过账本流水完成，不能直接 update user set balance = balance + xxx。
3. 开奖 / 活动结算流程
   第二张图核心流程是：
   注册 DApp
   充值 USDT
   系统选码 / 报码
   每天 21:34 开奖
   判断中奖 / 不中奖
   中奖：47 倍秒转 USDT，扣除一定比例
   不中奖：获得小六币奖励、返水
   如果做成合规系统，可以抽象为：
   活动期数
   用户订单
   活动结果
   结算任务
   奖励分配
   失败重试
   幂等控制
   注意：

如果是彩票或博彩形式，必须有合法资质。否则只能做成模拟盘、内部测试、积分活动、抽奖活动，不能涉及真实现金或 USDT 返奖。
4. 中奖分润规则
   图中中奖后大概有这些规则：
   中奖 47 倍
   自动扣除 20%
   其中：
   2% 打入小六币底池，用于回购销毁
   4% 分润
   代理 1%，平级 0.1%
   工会 0.5%
   董事 0.3%
   平台 2.1%
   这里有一个明显问题：
   图中说“自动扣 20%”，但明细只写了 2% + 4% = 6%，剩余 14% 没有说明。
   这个在做系统前必须确认，否则结算规则会不完整。
   系统实现时建议把这些比例全部做成后台可配置规则，不要写死在代码里。
5. 不中奖返还规则
   图中不中奖有两类奖励：
   A. 小六币奖励
   不中奖奖励 5% 小六币基金
   领取后自动兑换小六币
   每天 0.5% 释放
   这需要设计：
   小六币奖励记录
   锁仓记录
   释放计划
   每日释放任务
   已释放数量
   未释放数量
   提前释放 / 失效规则
   B. 返水规则
   图中写的是：
   自动结算水钱
   总返水 4.4%
   级差制
   可以自助开设下级返水比例
   代理 4%，平级 0.4%
   挂靠小店 3%，平级 0.3%
   普通会员 2%
   这里也需要确认：
   4.4% 是平台最大返水池，还是某种封顶值？
   代理 4%、普通会员 2% 是返给用户本人，还是返给上级？
   “级差制”具体是按上级差额计算，还是每一级都固定拿？
   平级收益是否只给最近一个平级上级？
   是否有层级上限？
   是否有日封顶 / 月封顶？

   二、推荐的合规版系统定位
   建议不要叫“资金盘”，而是改造成：
   用户积分活动系统 / 会员营销奖励系统 / 活动抽奖模拟系统
   合规化调整建议：
   原图功能	合规建议
   USDT 充值	改为法币支付通道或测试币；真实 USDT 需合规托管与 AML
   47 倍中奖	改成积分抽奖或优惠券奖励

   回购销毁	改成积分回收或活动消耗
   固定收益/释放	改成任务奖励、签到释放、积分有效期
   代理/工会/董事	改成会员等级，不与拉人头收益强绑定
   每日开奖	改成活动开奖，需要公示规则与概率

   五、Redis 使用场景
   Redis 不建议存最终余额，但可以用于：
   场景	Redis 用法
   登录态	JWT 黑名单 / Session
   验证码	手机/邮箱验证码
   规则缓存	奖励比例、系统配置
   分布式锁	每期结算锁、订单结算锁
   幂等控制	防止重复提交
   限流	注册、登录、下单、提现
   排行榜	活动排行，可异步落库
   延迟队列	简单释放任务，复杂场景建议用 MQ
   典型锁：
   lock:issue:settle:{issueNo}
   lock:order:settle:{orderId}
   lock:wallet:{userId}:{assetCode}
   lock:token:release:{userId}
   六、核心结算流程建议
1. 注册流程
   用户输入邀请码
   校验邀请码是否存在
   创建用户
   绑定上级关系
   创建钱包账户
   初始化会员等级
   写注册日志
2. 充值流程
   用户发起充值
   创建充值订单
   监听支付结果或后台确认
   校验金额、订单号、链上交易哈希
   入账钱包
   写钱包流水
   触发充值奖励事件，若合规允许
3. 活动参与流程
   用户选择活动期号
   校验余额
   冻结或扣减参与金额
   创建订单
   等待开奖
   进入结算队列
4. 开奖结算流程
   定时任务在指定时间触发
   使用 Redis 分布式锁锁住期号
   查询所有未结算订单
   判断中奖/未中奖
   创建结算记录
   发放奖励或返还积分
   生成返佣事件
   更新订单状态
   更新期号状态
   记录审计日志
5. 每日释放流程
   定时扫描释放计划
   判断是否到释放时间
   计算本次可释放数量
   入账用户小六币 / 积分钱包
   更新释放计划
   写释放流水
   防止重复释放
   七、需要你进一步确认的关键问题
   在真正开发前，这些规则必须确认清楚。

   你要做的是哪一种？
   A. 合规积分营销系统
   B. 内部模拟盘，不接真实资金
   C. 持牌彩票平台
   D. 真实 USDT 资金系统

2. 小六币定位
   小六币到底是：
   平台积分？
   链上 Token？
   可交易资产？
   只用于内部兑换？
   是否能提现？
   是否有价格？
   价格由谁决定？
3. 中奖扣费规则
   图中说中奖扣 20%，但只拆出来 6%。
   需要确认：
   剩余 14% 去哪里？
   是平台收入？
   是奖池？
   是销毁？
   是其他分润？
4. 返佣层级
   需要确认：
   返佣最多几级？
   是否只给直推？
   是否存在无限代？
   平级奖励给几个人？
   级差制公式是什么？
   是否有封顶？
5. 释放规则
   需要确认：
   每天释放 0.5% 是按原始奖励总量，还是剩余额度？
   是否用户需要手动领取？
   释放周期多少天？
   是否过期？
   释放时按什么价格折算小六币？
