# Debox 合规积分活动与会员奖励系统开发文档

## 1. 项目定位

本系统定位为“合规积分活动 + 会员邀请奖励 + 钱包账本 + 后台可配置规则”的后端服务。系统不实现非法彩票、赌博、资金盘、传销、多级拉人头收益或无资质虚拟资产交易功能。涉及真实资金、链上资产、抽奖、返佣、兑换时，必须先完成当地法律合规、支付资质、KYC/AML、税务与风控审查。

## 2. 技术架构

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 应用框架 | Spring Boot 3.x | REST API 与业务服务 |
| ORM | MyBatis-Plus | CRUD、分页、Mapper |
| 数据库 | MySQL 8.x | 用户、账本、订单、规则 |
| 缓存 | Redis 7.x | 配置缓存、幂等、分布式锁、限流 |
| 构建 | Maven | 依赖与构建管理 |
| 金额 | BigDecimal | 禁止使用 double/float 计算金额 |

## 3. 模块划分

### 3.1 用户中心 `user`
- 用户注册、邀请码生成、上级绑定。
- 用户角色：普通会员、小店、代理、工会、董事、平台管理员。
- 用户状态：正常、冻结、注销。

### 3.2 钱包账本 `wallet`
- 支持多资产账户，例如 `POINT` 积分、`BONUS` 奖励值。
- 钱包余额分为可用余额和冻结余额。
- 所有余额变动必须生成 `wallet_ledger` 流水。
- MySQL 是余额最终来源，Redis 不存最终余额。

### 3.3 活动订单 `activity`
- 活动期号、用户参与订单、活动结果、结算状态。
- 定时任务负责关闭期号、生成结果、结算订单。
- 需要 Redis 分布式锁防止重复开奖/重复结算。

### 3.4 奖励规则 `reward`
- 后台配置奖励事件、角色、资产、比例、封顶、有效期。
- 奖励发放进入 `reward_record`，再由钱包账本入账。
- 高风险的多级返佣默认不启用，建议只保留一级邀请奖励。

### 3.5 风控审计 `risk/audit`
- 登录/注册/下单/提现频率限制。
- 黑名单、设备/IP 限制、管理员操作日志。
- 重要资金流水、奖励记录、配置变更不可物理删除。

## 4. 核心数据表

| 表名 | 模块 | 说明 |
| --- | --- | --- |
| `sys_user` | 用户 | 用户基础信息、邀请码、上级、角色 |
| `user_invite_relation` | 用户 | 推荐关系快照 |
| `wallet_account` | 钱包 | 用户多资产账户 |
| `wallet_ledger` | 钱包 | 钱包流水，不可删除 |
| `activity_issue` | 活动 | 活动期号 |
| `activity_order` | 活动 | 用户参与活动订单 |
| `reward_rule` | 奖励 | 可配置奖励规则 |
| `reward_record` | 奖励 | 奖励发放记录 |

## 5. 核心流程

### 5.1 注册流程
1. 校验用户名/手机号唯一性。
2. 校验邀请码是否存在。
3. 创建用户并生成邀请码。
4. 保存推荐关系。
5. 初始化默认钱包账户。

### 5.2 钱包变动流程
1. 调用业务服务生成唯一业务单号。
2. 使用 Redis 或数据库唯一索引保证幂等。
3. 通过事务更新钱包余额。
4. 写入钱包流水。
5. 返回业务结果。

### 5.3 活动参与流程
1. 查询开放中的活动期号。
2. 用户提交参与订单。
3. 校验用户状态和活动状态。
4. 创建活动订单，必要时冻结积分。
5. 等待活动结算。

### 5.4 活动结算流程
1. 定时任务获取待结算期号。
2. 获取 `lock:activity:issue:{issueNo}` 分布式锁。
3. 计算活动结果并锁定期号。
4. 扫描未结算订单。
5. 生成奖励记录和钱包流水。
6. 标记订单已结算，释放锁。

## 6. Redis Key 规划

| Key | 用途 |
| --- | --- |
| `lock:activity:issue:{issueNo}` | 期号结算锁 |
| `lock:wallet:{userId}:{assetCode}` | 钱包余额变动锁 |
| `idem:{bizNo}` | 幂等控制 |
| `config:reward-rules` | 奖励规则缓存 |
| `rate:register:{ip}` | 注册限流 |

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/users/register` | 用户注册 |
| `GET` | `/api/users/{id}` | 用户详情 |
| `GET` | `/api/wallet/accounts/{userId}` | 用户钱包账户 |
| `POST` | `/api/activity/orders` | 创建活动参与订单 |

## 8. 开发阶段

### 第一期：基础骨架
- Maven/Spring Boot 工程。
- MyBatis-Plus、MySQL、Redis 配置。
- 用户、钱包、活动、奖励模块实体与 CRUD 骨架。

### 第二期：核心业务
- 注册邀请链路。
- 钱包入账/扣账/冻结/解冻。
- 活动订单创建与结算任务。
- 奖励规则配置与发放。

### 第三期：后台与风控
- 后台管理接口。
- 操作日志、黑名单、限流。
- 财务报表与对账。

## 9. 关键约束
- 所有金额字段使用 `DECIMAL(36,18)` 与 `BigDecimal`。
- 所有余额变动必须在事务中完成。
- 所有奖励发放必须具备唯一业务单号。
- 不允许物理删除钱包流水、奖励记录、订单记录。
- 不将 Redis 作为最终账本。
